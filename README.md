# Dragger
퍼블리싱에 대한 죄책감을 덜어주는 서비스.

개발 화면에서 UI를 편집하고, 수정한 값만 검토해 GitHub·Bitbucket의 PR 작성 화면으로 전달하는 로컬 도구입니다. 서비스 코드와 계정 정보는 배포물에 포함하지 않습니다.

## AI와 함께 설치하기 · MCP 초기 버전

[AI용 설치 안내](docs/AI-SETUP.md)를 사용하는 AI 코딩 도구에 전달하세요. 로컬 stdio MCP 및 파일·명령 실행이 가능한 환경을 대상으로 합니다.

```sh
npm ci --ignore-scripts
npm test
```

MCP 실행 파일은 `bin/mcp.mjs`입니다. AI가 준비 상태 확인, 편집기 실행, 프로젝트 등록, UI 변경 읽기·검토, 검증된 변경의 PR 브랜치 준비를 호출할 수 있습니다. 인증 토큰은 브라우저에서 입력하며, 코드 적용과 화면 확인도 기존 편집기에서 진행합니다. **회사 앱을 자동 실행하거나 모든 AI 클라이언트를 지원하는 완성형 설치 앱은 아닙니다.**

공식 MCP SDK 클라이언트와 자동 테스트를 기준으로 검증합니다. 각 AI 제품별 설치와 Windows 더블클릭 사용성은 별도 검증 대상입니다.

## 팀원이 시작하는 방법

1. 개발자가 준비한 Dragger 폴더에서 macOS는 **Dragger 시작.command**, Windows는 **Start-Dragger.cmd**를 엽니다. Node.js 20 이상이 한 번 설치돼 있어야 합니다. 브라우저가 자동으로 열립니다. 실행 창을 닫으면 서버도 종료되므로 편집 중에는 유지하세요.
2. **서비스 연결 → 시작하기 · 연결 상태**를 엽니다. 처음 실행해서 서비스가 없으면 자동으로 나타납니다.
3. 팀 연결 JSON 파일을 불러오거나 서비스 이름·개발 화면 주소·이 컴퓨터의 원본 폴더를 입력합니다. 저장하면 서버를 다시 켜도 기억합니다.
4. **편집 화면 열기**를 누릅니다. 앱을 실행한 상태에서 필요한 계정으로 로그인하고 원하는 화면으로 이동합니다. 원본 폴더 등록과 화면 편집 연결은 별도로 확인합니다.
5. UI를 수정하고 최종 검토에서 변경 내용을 확인합니다. 원본 코드 적용 후 실제 화면을 확인합니다.
6. PR을 보낼 때 GitHub 또는 Bitbucket을 연결합니다. 변경 브랜치를 업로드한 뒤 해당 웹사이트에서 PR을 최종 등록합니다. 웹 작성 페이지가 열렸다는 것만으로 PR이 생성된 것은 아닙니다.

앱을 실행하거나 연결할 수 없다면 시작하기의 **개발자에게 준비 요청하기** 내용을 복사해서 전달하세요. 회사 앱의 백엔드·로그인·테스트 데이터는 Dragger가 자동으로 만들지 않습니다.

### 내 앱의 여러 페이지 편집하기

1. 자신의 앱을 평소처럼 실행합니다. 로컬 프런트엔드를 회사 개발용 백엔드에 연결해도 되며, 백엔드까지 반드시 내 컴퓨터에서 실행할 필요는 없습니다.
2. **내 앱 연결 · 원본 폴더 등록**에서 브라우저로 열리는 앱 주소와 해당 앱의 원본 폴더를 등록합니다. API 주소나 Git 저장소 주소를 앱 주소 칸에 넣지 않습니다.
3. **앱 열기 · 로그인**으로 앱을 직접 열어 필요한 계정으로 로그인합니다. Dragger와 앱을 같은 브라우저에서 열어 주세요. 브라우저의 쿠키 정책이나 회사 SSO가 iframe 로그인을 제한하면 팀 개발자의 개발 환경 설정이 필요할 수 있습니다.
4. 편집기로 돌아와 **다시 확인 → 편집 화면 열기**를 누릅니다. UI 편집 패널을 닫은 상태에서 앱 메뉴를 클릭하거나 상단 주소에 같은 서비스의 페이지 주소를 입력합니다. 원하는 화면에 도착하면 **UI 편집하기**를 켭니다.
5. 원본 연결은 공통 레이아웃에 한 번 설치합니다. 로그인한 계정이 접근할 수 있고 데이터가 준비된 페이지에서 계속 편집할 수 있습니다. 관리자 전용 화면, 데이터가 없는 상세 화면, 별도 도메인 앱은 각각 접근 권한·데이터·연결 준비가 필요합니다.

연결 상태의 **앱 응답 확인됨**은 서버 응답만 확인한 결과입니다. 로그인 성공·백엔드 연결·모든 화면의 편집 가능 여부를 보장하지 않습니다. 샘플 데이터로 실행한 앱은 실제 서비스 연결을 대신하지 않습니다. 앱과 Dragger 실행 창은 편집 중 유지하세요.

## 개발자가 한 번 준비할 사항

현재 원본 연결 지원 대상은 React / Next.js webpack 개발 환경입니다.

1. 대상 앱의 의존성과 TypeScript를 설치하고, 개발 서버 및 필요한 백엔드를 준비합니다.
2. Next webpack 설정에서 `dev && process.env.DRAGGER_SOURCE === '1'`일 때 Dragger의 `lib/source-loader.cjs`를 `src`의 `.tsx`/`.jsx`에 `enforce: 'pre'` 로더로 연결합니다. 앱은 `DRAGGER_SOURCE=1 next dev --webpack`으로 실행합니다.
3. 개발 환경의 공통 레이아웃에서 브리지를 로드합니다. 앱의 iframe 허용 정책도 확인합니다.

```html
<script src="http://127.0.0.1:4317/bridge.js" data-dragger-origin="http://127.0.0.1:4317"></script>
```

4. Dragger의 시작하기에서 원본 폴더와 화면 주소를 등록하고, 실제 요소를 선택해 원본 연결을 확인합니다. 로더는 해당 요소의 파일·순번·버전을 붙입니다. 클래스 이름만으로 코드를 추측하지 않습니다.
5. **팀 연결 파일 저장**으로 이름·화면 주소만 공유합니다. 각 팀원에게 자신의 원본 폴더와 앱 실행 환경이 필요합니다. localhost 주소는 받는 사람의 컴퓨터를 뜻합니다. 비밀번호·토큰·개인 경로는 연결 파일에 담지 않습니다.

개발용 직접 실행은 `npm start`, 검증은 `npm install` 후 `npm test`입니다. 기존 `DRAGGER_REPO`, `DRAGGER_APP_ORIGIN` 환경변수도 처음 등록할 때 사용할 수 있습니다. 저장된 설정이 있으면 저장된 값을 우선 사용합니다. 원본 폴더는 한 번에 하나 활성화됩니다. 코드 적용 작업이 남아 있으면 다른 폴더로 전환하기 전에 마무리하세요.

## 저장과 복구

- 원본 폴더 연결은 `.local/project.json`에 저장합니다. 이 파일에는 개인 경로가 있으므로 배포하거나 커밋하지 않습니다.
- 서비스 주소와 편집 초안은 해당 브라우저의 로컬 저장소에 보관됩니다. 원본 연결된 UI 변경값은 AI 검토를 위해 서버의 `.local/drafts/`에도 동기화됩니다. MCP에서 변경 읽기·검토를 요청하면 연결된 AI에 코드와 텍스트가 전달될 수 있으므로 회사의 AI 이용 정책을 따르세요. 브라우저 데이터를 지우면 복구되지 않으며 다른 컴퓨터에 자동 동기화되지 않습니다.
- API 토큰은 서버 메모리에만 보관합니다. 서버 재시작 후에는 인증을 다시 해야 합니다. 저장소 주소와 편집 초안은 유지됩니다.
- 적용 기록과 백업은 운영체제 임시 폴더에 보관합니다. 시스템 정리로 삭제될 수 있으므로 장기 백업은 Git을 사용하세요.
- 실행 취소·다시 실행, 선택 요소 복원과 코드 적용 되돌리기를 지원합니다. 적용 후 다른 수정이 생겼으면 덮어쓰지 않고 중단합니다.

## 변경 범위와 PR

UI 편집 패널의 **편집 범위**에서 **선택한 요소만** 또는 **공용 컴포넌트**를 고릅니다. 새 요소를 선택하면 기본값은 선택한 요소만입니다. 범위 전환은 이후 수정값부터 적용되며 기존 변경을 소급해서 바꾸지 않습니다.

- 선택한 요소만: 확인 가능한 사용처의 prop/클래스를 수정합니다. 공용 내부 요소나 반복 요소를 안전하게 분리할 수 없으면 코드 적용을 중단합니다.
- 공용 컴포넌트: 선택한 원본 요소의 기본값을 수정합니다. 현재 요소에서 미리 보고, 다른 사용처는 코드 적용 후 반영됩니다. 지원되는 아이콘은 개별 color prop과 색상 클래스가 우선하도록 유지합니다. 이미 개별 색상을 지정한 사용처에서는 공용 기본색 편집을 중단합니다.
- 같은 속성의 개별 변경과 공용 변경은 한 번에 적용하지 않습니다. SVG 이미지 파일의 색상 변경은 공용 범위에서만 새로 만들 수 있습니다.

선택한 JSX 요소의 스타일을 변경합니다. 고정된 Tailwind 텍스트 색상 클래스와 색상 토큰이 있으면 기존 클래스를 교체합니다. 선택한 요소만 모드에서 지원되는 공용 아이콘은 화면에서 선택한 사용처를 추적해 color prop 또는 currentColor용 클래스를 수정하며, 공용 아이콘 파일을 덮어쓰지 않습니다. 사용처·색상 전달 방식이 불명확하거나 기존 인라인 덮어쓰기가 남아 있으면 자동 적용을 중단합니다. 그 외 지원 스타일은 기존 표현식을 보존한 인라인 스타일로 적용합니다. 단순 JSX 문구와 고정 키의 next-intl 번역, 색상·Flex·위치·크기, 지원되는 SVG 색상을 편집할 수 있습니다. 동적 텍스트나 모호한 소스는 추측해서 수정하지 않습니다.

공유 컴포넌트·SVG의 수정은 다른 화면에도 영향을 줄 수 있습니다. 화면 반영 확인은 선택한 변경값 검증이며 모든 화면의 시각적 회귀 검사를 뜻하지 않습니다. 모바일·PC 공용 소스는 양쪽에 적용될 수 있습니다.

GitHub·Bitbucket 연결에는 회사에서 허용한 토큰 및 저장소 접근 권한이 필요합니다. UI에서 연결 방법을 안내합니다. PR 준비 시 별도 브랜치에 변경을 업로드하고 웹 작성 페이지를 엽니다. 자동 병합하지 않습니다. 브라우저에서 PR을 최종 등록하세요.

## 기타 연결 방식

고정 `data-dragger-id`가 있는 요소는 JSON/CSS 내보내기를 지원합니다. 개발자가 생성 CSS를 제품 스타일 뒤에 연결해야 합니다. CLI 사용법:

```sh
node bin/dragger.mjs plan changes.json --repo /path/to/product
node bin/dragger.mjs apply changes.json --repo /path/to/product
```

CLI의 `pr` 명령은 GitHub CLI 인증과 명시적 `--publish` 옵션이 필요한 별도 경로입니다.

`extension/`은 개발용 Chrome 확장입니다. 현재 페이지의 미리보기 편집을 위한 초기 버전이며, 설치만으로 임의 사이트와 원본 저장소가 자동 연결되지는 않습니다. 스토어 배포·설치 검증은 별도로 필요합니다.
